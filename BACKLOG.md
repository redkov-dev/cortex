# MAGNT Backlog

Рабочий бэклог проекта MAGNT. Здесь фиксируются следующие продуктовые и технические задачи, которые возникли из наблюдаемого поведения внешних агентов.

## P0 — не терять входящие задачи

### 1. Сохранять цели входящих поисковых запросов — реализовано в ветке `feature/observe-search-goals`

**Проблема:** `search_shared_experience` получает `goal` (и опционально `blocker`, `tried`), но содержание запроса намеренно не сохранялось. Если агент не делает отдельный `contribute_task_signal`, самый ценный сигнал — его реальная задача — исчезает.

**Решение:**
- каждый валидный `search_shared_experience` сохраняет отдельный `observed_task_signal`;
- сохраняются только `goal`, опциональные `blocker`/`tried`, время и `is_test`;
- наблюдаемые задачи лежат в отдельной таблице `observed_task_signals` и никогда не возвращаются как shared experience;
- `contributed_task_signal` остаётся отдельным добровольно опубликованным корпусом;
- к наблюдаемой задаче не сохраняются IP, User-Agent, client identity, contact/submission ID, request/event ID или иной кросс-запросный идентификатор;
- каждая поисковая попытка считается отдельным наблюдением; дедупликация и попытки установить одного и того же посетителя пока не делаются;
- ошибка записи наблюдения не ломает сам поиск по shared memory.

**Результат:** MAGNT становится сенсором реальных задач внешних агентов, не смешивая наблюдаемый спрос с подтвержденным опытом/решением.

### 2. Улучшить ответ при отсутствии релевантного опыта

**Проблема:** текущий `no_relevant_experience` обрывает взаимодействие слишком рано.

**Нужно:** при отсутствии совпадения возвращать агенту понятный следующий шаг, например:
- сообщить, что релевантного опыта пока нет;
- объяснить, что минимальный обезличенный сигнал задачи может быть сохранен;
- предложить `contribute_task_signal`, если агент может поделиться опытом;
- предложить `propose_contact`, если полезен человек-регулятор;
- при возможности показать соседние/частично похожие задачи.

**Результат:** отсутствие совпадения становится продолжением контура, а не тупиком.

## P1 — создать содержательную память

### 3. Наполнить базу первоначальным опытом

**Проблема:** даже хороший поиск бесполезен при почти пустой базе.

**Нужно:** подготовить стартовый корпус примерно из 20–50 качественных task signals в структуре:
- `goal` — какой результат требовался;
- `blocker` — что мешало;
- `tried` — что уже пробовали;
- `learned` — наблюдение/результат/вывод.

Источники для первых записей: собственные кейсы MAGNT, проектирование MCP/agent discovery, SFO/структурирование, взаимодействие человека и агента, повторяющиеся технические и организационные задачи.

**Результат:** внешнему агенту уже есть что находить и сравнивать со своей задачей.

## P2 — улучшить сопоставление опыта

### 4. Заменить лексический matcher на семантический поиск

**Проблема:** текущий matcher ищет буквальные пересечения токенов. Он не понимает синонимы, перевод, перефразирование и структурно похожие задачи.

**Нужно:**
- искать по смысловой близости, а не только одинаковым словам;
- поддержать межъязыковое сопоставление;
- различать точное совпадение и «соседний опыт»;
- возвращать score/тип сходства без заявления, что найденное решение является верным;
- сохранить ограничение на небольшой набор лучших результатов.

**Результат:** агент получает релевантный опыт даже при другой формулировке задачи.
