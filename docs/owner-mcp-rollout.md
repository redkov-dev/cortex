# MAGNT Owner — включение выпуска B

Личный MCP Александра: **`https://magnt.ru/mcp-owner`**. Он читает сохранённые
контакты и цели, хранит частные черновики, позволяет отметить просмотренное,
архивировать и вернуть запись. Публикация ответа посетителю появится в выпуске C.

Код поставляется выключенным. Cloudflare настраивает Александр; доступ к панели,
пароли и токены передавать ассистенту не требуется. Telegram продолжает работать
во время настройки. Его токен, chat ID и `NOTIFY_FROM` менять не нужно.

## 1. Подготовить D1

Убедись, что новая версия Worker из основной ветки развёрнута. В **Storage &
databases → D1 → magnt-contacts → Console** выполни SQL из
[0006_owner_workspace.sql](../cloudflare/magnt-observer/migrations/0006_owner_workspace.sql)
целиком, без Markdown-ограждений. Миграции 0001–0005 уже должны быть применены.
Не запускай удаление или пересоздание прежних таблиц.

Проверка:

```sql
SELECT name FROM sqlite_master
WHERE type = 'table' AND name IN (
  'owner_workspace_state', 'owner_inbox', 'owner_replies', 'owner_operations'
) ORDER BY name;
SELECT revision FROM owner_workspace_state WHERE singleton = 1;
```

Ожидаются четыре имени и ревизия `1` при первом применении. Сообщение `No data`
после CREATE нормально; `No SQL statements detected` означает, что SQL не выполнен.
Новые таблицы не копируют тексты контактов и не запускают уведомления задним числом.

## 2. Создать личный вход в Cloudflare Access

Открой **Zero Trust → Access controls → Applications → Add an application →
Self-hosted**. Название — `MAGNT Owner`. Zero Trust должен быть в том же аккаунте,
что Worker и домен. Для одного пользователя ориентир — бесплатный тариф, если
он доступен в аккаунте; платный тариф для этой реализации не требуется.

Защити **только** `magnt.ru/mcp-owner` и дочерние пути, включая
`magnt.ru/mcp-owner/identity`. Если форма требует отдельные записи, добавь пути
`mcp-owner` и `mcp-owner/*` к домену `magnt.ru`. Публичный `/mcp` и весь сайт
в это приложение не включай.

Политика **Allow**: только твой точный адрес email, вход через выбранного
поставщика либо One-time PIN. Не добавляй `Everyone`, `Bypass` или Service Auth.
Длительность обычной Access-сессии для пилота — 15 минут.

В **Advanced settings** включи **Managed OAuth**. Это отдельная возможность:
обычная страница входа Access не обеспечивает подключение ChatGPT.
Выбери access token lifetime **15 minutes**, grant session **24 hours**;
localhost и loopback clients выключены.

Для регистрации OAuth-клиента разреши точный **Redirect URI**, показанный
при создании подключения в ChatGPT. Если до создания его ещё нет, для первичной
настройки допустимы только эти адреса ChatGPT:

```text
https://chatgpt.com/connector/oauth/*
https://chatgpt.com/connector_platform_oauth_redirect
```

После создания подключения замени их точным адресом из его настроек.
Не используй маску для всего Интернета и не подставляй старый callback наугад.

Сохрани приложение. Скопируй **Application Audience (AUD)** из его настроек
и адрес своей команды `https://ИМЯ-КОМАНДЫ.cloudflareaccess.com`.

## 3. Настроить Worker и закрепить владельца

В **Workers & Pages → magnt-observer → Settings → Variables and Secrets**
добавь значения в Production. Это новые переменные:

| Имя | Значение |
| --- | --- |
| `OWNER_MCP_ENABLED` | Пока `false` |
| `OWNER_MCP_WRITE_ENABLED` | Пока `false` |
| `OWNER_ACCESS_ISSUER` | Точный `https://ИМЯ-КОМАНДЫ.cloudflareaccess.com`, без `/` в конце |
| `OWNER_ACCESS_AUD` | AUD именно приложения MAGNT Owner |
| `OWNER_ACCESS_SUB` | Будет получен следующим шагом; пока не добавляй |

Сохрани и разверни настройки. В браузере открой
**`https://magnt.ru/mcp-owner/identity`**, войди своим разрешённым аккаунтом.
Страница вернёт JSON с `issuer` и `subject`. Скопируй **subject** в
`OWNER_ACCESS_SUB`. Это идентификатор пользователя Access, **не Telegram user ID**.
Он не является паролем; его можно хранить как переменную или Secret.
Настроечная страница не читает базу MAGNT и возвращает только личность вошедшего.

После сохранения subject установи `OWNER_MCP_ENABLED=true`, а запись пока
оставь выключенной. Не добавляй эти значения в публичный репозиторий.

## 4. Подключить второй MCP в ChatGPT

Добавь отдельное личное подключение так же, как публичный MAGNT:

- название: **MAGNT Owner**;
- URL: **`https://magnt.ru/mcp-owner`**;
- авторизация: **OAuth**, с обнаружением параметров и динамической регистрацией
  клиента (DCR), если интерфейс предлагает выбор;
- вход: твой разрешённый аккаунт Access.

Публичный MAGNT сохраняется отдельным подключением. Секрет бота, subject и
проектные токены в поля OAuth Client Secret не вставляются. При DCR отдельные
Client ID/Secret вручную не создаются.

Ожидаются четыре инструмента: `list_inbox`, `read_conversation`, `write_reply`,
`update_inbox`. Сначала попроси: «Покажи входящие MAGNT Owner», затем
«Открой цель ots_…» или «Открой обращение mc_…», взяв ID из своего Telegram.
Чтение не ставит отметку «просмотрено». Тесты по умолчанию скрыты.

**Если подключение не проходит:** не отключай защиту Access. Проверь точный
callback, включённый Managed OAuth, совпадение issuer/AUD/subject и доступность
OAuth discovery. Открытие `https://magnt.ru/.well-known/oauth-authorization-server`
должно давать metadata от Access; HTTP-клиент без авторизации на `/mcp-owner`
должен получать OAuth challenge, а не HTML-страницу. В metadata требуется PKCE
`S256` и поддерживаемая регистрация клиента. Если вместо metadata приходит
Worker `not_found` или прокси-страница, конфигурация edge ещё не готова.
Проверка подписи в Worker самостоятельно OAuth discovery не заменяет.

Фактическая совместимость твоего аккаунта с этой конфигурацией подтверждается
этим входом и вызовом инструмента, а не только локальными тестами сервера.

## 5. Разрешить черновики и принять результат

После успешного чтения установи `OWNER_MCP_WRITE_ENABLED=true` и разверни
настройку. Команды для работы:

- «Сохрани к этому обращению черновик: …» — частный текст в D1.
- «Отметь это обращение просмотренным» — явная отметка входящего события.
- «Архивируй это обращение» / «Верни его из архива» — управление очередью.

Для приёмки используй **тестовый контакт** (`is_test=true` через публичный
`propose_contact`, либо уже существующий тест). В Owner запроси
`include_tests=true`, открой его, сохрани явно помеченный тестовый черновик.
Открой из нового чата и проверь, что черновик остался. Повтор с тем же
`submission_id` и аргументами должен вернуть прежнюю квитанцию без дубля.
Попытка `mode=publish` должна дать `reply_channel_unavailable`, ничего не отправив.

Дополнительно проверь отказ входа с другого аккаунта и отказ записи при
`OWNER_MCP_WRITE_ENABLED=false`. Для проверки отзыва отключи владельческие
операции серверным флагом: даже ранее выданный токен не должен их разрешать
после развёртывания настройки. В журнале приёмки укажи даты проверки, версию кода,
применение 0006 и результат настоящего OAuth-подключения.

После включения Owner новые Telegram-уведомления предлагают открыть исходную
запись в этом подключении. `metadata_only` по-прежнему не передаёт текст в Telegram.

## Отключение и диагностика

`OWNER_MCP_WRITE_ENABLED=false` оставляет чтение и запрещает все изменения,
включая повторы. `OWNER_MCP_ENABLED=false` отключает владельческие инструменты.
Оба действия требуют сохранения/развёртывания настройки. Публичный MCP и
Telegram от этих флагов не отключаются. Таблицы и черновики при откате не удаляй.

| Ответ | Что проверить |
| --- | --- |
| `owner_disabled` | Флаг Owner ещё выключен |
| `owner_configuration_required` | issuer/AUD/subject отсутствуют либо неверного формата |
| `unauthenticated` | Access assertion отсутствует, недействителен или просрочен; повторить вход |
| `forbidden` | Другой subject либо запись выключена |
| `storage_unavailable` | Миграция 0006, прежние миграции и binding CONTACTS |
| `invalid_cursor` | Начать чтение заново без курсора: состояние изменилось |
| `revision_conflict` | Перечитать запись перед изменением, сохранив подготовленный текст |
| `reply_channel_unavailable` | Ожидаемо в B: публичная выдача ответов ещё не реализована |

`list_inbox` возвращает сводку Telegram-очереди; недоступность диагностики
уведомлений не блокирует чтение источников. При `has_more=true` продолжай чтение
даже после пустой страницы: сервер ограничивает число просматриваемых записей.

Авторизация Access проверяет политику заново при обновлении OAuth-токена;
мгновенный отзыв уже выданного токена не обещается. Для срочной остановки
используются серверные флаги. Тексты и токены не отправляй в диагностические
скриншоты. В Worker трассировка отключена, query string редактируется;
дополнительные Access/Logpush-журналы проверяются отдельно.
