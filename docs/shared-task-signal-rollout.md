# Запуск Shared Task Signal MVP

Цель: сохранить текущий Human Endpoint и добавить два инструмента. Новая база
не нужна: используется `magnt-contacts`, binding `CONTACTS`.

## Ручной шаг владельца: создать таблицу

Выполнить **до слияния этой версии в production-ветку `main`**:

1. В Cloudflare открыть **Storage & databases → D1 → magnt-contacts → Console**.
   Названия разделов могут отличаться; нужна SQL-консоль уже существующей базы.
2. Скопировать весь SQL из
   [`0002_task_signals.sql`](../cloudflare/magnt-observer/migrations/0002_task_signals.sql)
   и выполнить его. Скрипт создаёт только `task_signals` и её индекс; существующие
   сообщения в `contacts` не изменяет. Если консоль принимает только один оператор,
   выполнить `CREATE TABLE` и `CREATE INDEX` по отдельности.
3. Проверить результат:

```sql
SELECT name FROM sqlite_master
WHERE type = 'table' AND name IN ('contacts', 'task_signals')
ORDER BY name;
```

Должны отображаться обе таблицы. Пароли, токены и содержание обращений передавать
не нужно; для продолжения достаточно подтверждения успешного выполнения.

Скрипт допускает повторное применение. Ручной запуск не добавляет строку в
служебную таблицу истории Wrangler; при последующем `db:migrate` эта миграция
безопасно выполнится ещё раз и будет отмечена штатным механизмом.

## Публикация и проверка

После подтверждения миграции:

1. Слить проверенную рабочую ветку в `main`.
2. Дождаться успешной проверки **Workers Builds: magnt-observer** для нового
   коммита. Проверка GitHub Pages сама по себе не подтверждает деплой Worker.
3. Проверить `/__magnt_probe`: `mcp_door_version = 0.2.0`,
   `shared_memory_version = 0.1.0`, оба storage-флага равны `true`.
   Эти флаги подтверждают наличие binding, а не исправность таблиц.
4. Из `cloudflare/magnt-observer` выполнить:

```sh
npm run smoke -- https://magnt.ru/mcp --shared-memory-test --submit-test
```

Тест проверяет четыре инструмента, профиль, чтение до/после явной записи,
идемпотентность, изоляцию тестовой записи и прежний канал личных сообщений.
Все записи помечены `is_test=true`, запросы — `MAGNT-Controlled-Test/0.2`.
Текст задач в отчёт теста не выводится. Только после успешного production smoke
технический MVP считается запущенным. Это ещё не успех внешнего эксперимента.

## Если есть настроенная CLI-авторизация Cloudflare

Вместо ручного SQL можно выполнить из каталога Worker:

```sh
npm run deploy:migrated
```

Команда последовательно выполняет `db:migrate` и `deploy`; при ошибке миграции
деплой не начинается. Для автоматизации можно назначить её Deploy command
существующего Cloudflare Builds после проверки прав его токена на D1. Простой
`npx wrangler deploy` не запускает D1 SQL-миграции. Настройки Cloudflare Builds
этой версией репозитория автоматически не изменяются.

## При ошибке

Если shared tools возвращают `storage_error`, проверить наличие таблицы,
binding и успешность миграции. Поиск не создаёт схему и не маскирует ошибку
результатом «нет совпадений». Старые инструменты продолжают работать независимо.
При необходимости вернуть предыдущую версию Worker и согласованные статические
документы через git revert; новую таблицу и существующие контакты не удалять.

`server.json` содержит манифест версии 0.2.0. Его изменение не публикует новую
версию в Official MCP Registry; публикация там проверяется отдельно и не является
условием работоспособности существующего адреса MCP.
