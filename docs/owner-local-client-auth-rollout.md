# MAGNT Owner — локальный OAuth-клиент: безопасное включение

Статус: **не активировано**; реализация в отдельном draft PR, не объединена с `main`.

## Решения владельца

Александр подтвердил **все пять существующих инструментов** Owner для MultiTool Home, право `magnt.owner.write` с момента выдачи, 90 суток абсолютного срока grant, 3600 секунд access, автоматический rotating refresh. Владелец явно принял риск хранения refresh в plaintext `~/.config/gigatool/agent/mcp-auth.json` на его Windows-машине. ACL ограничивает доступ, но это **не шифрование**; BitLocker не подтверждён. Нет попыток передавать токен через чат/GitHub.

## Последовательность включения — ручная, после ревью и зелёных тестов

1. Сверить с разработчиком MultiTool, что клиент принимает явный `clientId` и фиксированный redirect `http://127.0.0.1:19876/mcp/oauth/callback`. Порт **19876 должен быть свободен** и должен оставаться доступным системному loopback listener. Если он занят, освободить его и повторить подключение; смена порта требует нового заранее зарегистрированного клиента, а не wildcard. Другие пути/порты **не поддерживаются пилотом**; не разрешать wildcard и не запускать DCR. Не используйте общие клиентские credentials из ChatGPT.
2. До миграции сохранить резервную копию существующей D1 `magnt-contacts`. Убедиться, что `0007_dialogues.sql` уже применена. Выполнить **только** `npm run db:migrate:owner-local`, которая готовит конфигурацию с `0008_owner_local_grants.sql`. Проверить в D1 таблицу `owner_local_grants`, не переигрывать миграции 0001–0007 и не менять старые данные.
3. В приватном `magnt-core` оставить `OWNER_LOCAL_CLIENT_ENABLED=false`. Включить **только** `OWNER_LOCAL_CLIENT_SEED_ENABLED=true`, выполнить один плановый Cron (проверка, что core Owner включён), затем вернуть флаг в `false`. Эта операция вызывает `oauth.createClient` внутри ядра и сохраняет ID в `OAUTH_KV`; ключ `owner:local-client:registration:v1`. Прямого публичного маршрута для создания клиентов нет. Если сидирование прошло, повторно делать его не нужно.
4. **Повторно авторизовать основной ChatGPT Owner после выкладки нового кода**, а не только обновить список инструментов: ранее выданные токены не содержат `ownerClientClass: 'chatgpt'`, поэтому безопасно классифицируются как `unknown` и не видят инструменты управления локальными грантами. После повторного входа с `magnt.owner.write` обновить инструменты и вызвать `list_owner_grants`: прочитать `local_client.client_id` и `redirect_uri`. Это **публичный client ID**, а не секрет. Не передавать refresh/access/GitHub tokens.
5. В конфиге MultiTool Home указать URL `https://owner.magnt.ru/mcp`, полученный `clientId`, `redirectUri` из пункта 4 и scopes `magnt.owner.read magnt.owner.write offline_access`. При необходимости переоткрыть системный браузер.
6. Перед первым подключением активировать `OWNER_LOCAL_CLIENT_ENABLED=true` только на `magnt-core`. В браузере увидеть явный отдельный checkbox write — публикация ответов и операции с токенами **публичных диалогов**. Проверить GitHub numeric owner ID и не использовать другие аккаунты.
7. Проверить на **тестовом** диалоге все пять инструментов: `list_inbox`, `read_conversation`, `write_reply` в режимах draft/publish, `update_inbox`, `manage_dialogue_access` enable/rotate/revoke. Новые `list_owner_grants` и `revoke_owner_grant` недоступны локальному агенту и доступны основному доверенному Owner.
8. Подтвердить, что `read-only` при снятой галочке write запрещает прямой RPC к трём write-инструментам; `offline_access` при снятой галочке не выдаёт refresh; неверный resource/redirect/owner/PKCE отвергается; старый ChatGPT продолжает читать и писать.
9. Зафиксировать реальные квоты D1/KV/Worker CPU (пилот намеренно проверяет D1 при **каждом** локальном MCP вызове, чтобы отзыв не зависел от потенциально устаревшего кэша). Если тариф Free не выдерживает нагрузку — не скрывать проверку, а отдельно проектировать ограниченный кэш с измеренной задержкой отзыва.
10. После реального e2e проверить отзыв **одного** локального разрешения через `revoke_owner_grant(grant_id)`, не затрагивая ChatGPT; убедиться, что токены больше не работают и не обновляются. Для emergency: `OWNER_LOCAL_CLIENT_ENABLED=false` (для всех локальных клиентов), `OWNER_AUTH_EPOCH` (для всех Owner-сессий) или `OWNER_MCP_ENABLED=false`.

## Границы реализации

- Флаг `OWNER_LOCAL_CLIENT_ENABLED` по умолчанию off, сидирование — отдельный default-off флаг. Временное включение seed-флага нельзя оставлять постоянно.
- OAuth access 1 час. Вся логика 90 дней подтверждается **серверной D1-записью** для каждого индивидуального гранта, дополненной проверкой активированного состояния; refresh не продлевает expires_at. OAuth-библиотека применяет refreshTokenTTL при первичной выдаче, но не на каждом refresh — нельзя считать его единственной границей. Для локальных грантов idle TTL также ограничен оставшимся сроком 90-дневного разрешения. Повторное подключение после истечения создаёт новое разрешение. Для локального клиента намеренно указано `revokeExistingGrants: false` при `completeAuthorization`: иначе OAuth-библиотека отзывает предыдущие разрешения того же владельца и client ID, нарушая независимость нескольких установок. Независимость проверяется в интеграционном тесте.
- OAuth-библиотека допускает **один предыдущий refresh-токен** после ротации для восстановления потерянного ответа. Это её документированная одношаговая grace-политика, а не немедленная invalidation. Повторное использование более старого refresh должно отклоняться; истечение или отзыв гранта проверяются отдельно на сервере.
- Токены остаются под управлением установленной библиотеки `@cloudflare/workers-oauth-provider` и хранятся в ядре, а не в gateway. Хранилище OAuth-клиента на машине Мультитула — отдельно принятое решение владельца.
- Статус «ответ опубликован» означает доступность для polling через `get_dialogue`, а не факт прочтения посетителем.
- Подтверждение записи перед вызовом — клиентское правило/UX, **не** техническая серверная гарантия того, что команда действительно была дана человеком.
- Проект сознательно не добавляет новые маршруты на публичные Worker и не выдаёт локальному клиенту право управления OAuth grants других клиентов.

## Проверки сборки

Из root `cloudflare/magnt-observer`: `npm ci && npm test`. Тесты `test/owner-local-oauth.test.js` запускают Miniflare с миграцией 0008, отдельным тестовым seed-контролом и моками GitHub; **они не заменяют живой e2e**.

При ошибках не включать `OWNER_LOCAL_CLIENT_ENABLED`; не удалять D1/KV и не откатывать миграцию удалениями данных. Для быстрого rollback достаточно отключить `OWNER_LOCAL_CLIENT_ENABLED`; основной ChatGPT Owner остаётся в прежнем контуре.
