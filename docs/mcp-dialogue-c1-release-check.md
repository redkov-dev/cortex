Серверная функция включена и проверена в рабочем MAGNT. Проверка выполнена
в одной новой переписке с `is_test=true`; реальные обращения не изменялись.

## Развёртывание

- [PR #17](https://github.com/redkov-dev/cortex/pull/17) слит в `main`, коммит
  `0390fcf477deaee09176dee1f2efb4386f035377`.
- До выкладки прошли 106 локальных тестов и GitHub Actions; замечание ревью
  о пагинации Owner при остановке чтения исправлено и покрыто тестом.
- По предоставленному владельцем журналу Cloudflare миграция
  `0007_dialogues.sql` успешно выполнила 28 команд 7 ноября в 01:24 МСК.
  Затем успешно развёрнут `magnt-core`; D1, OAuth KV и три Rate Limiting binding
  присутствуют в журнале. Другие миграции этим запуском не выполнялись.

  **Deploy command** — `npm run deploy:core`.

## Проверка обмена

Публичная сторона проверена HTTP-запросами MCP с сохранением токена и курсора
в приватном локальном состоянии. Каждый запуск клиента повторно использовал
это состояние. Owner работал через существующее OAuth-подключение ChatGPT.
Проверка проводилась около 10:58–11:03 МСК.

| Проверка | Наблюдаемый результат |
| --- | --- |
| Новое обращение | Выданы токен, ID сообщения и инструкция вернуться через час; входящее непрочитано |
| Повтор создания с тем же UUID | Один контакт; секрет повторно не выдан |
| Опрос до ответа | `message=null`, статус входящего `unread` |
| Просмотр списка Owner | Входящее остаётся непрочитанным; доступна публикация |
| Публикация без открытия входящего | Два ответа опубликованы успешно; входящее остаётся непрочитанным |
| Получение первого ответа | Возвращён ровно один ответ, `has_more=true`; второй ответ ещё непрочитан |
| Повтор со старым курсором | Тот же ID ответа, текст и первое время прочтения |
| Получение второго ответа | Отдельный ответ; Owner показывает его как прочитанный; входящее всё ещё непрочитано |
| Полное открытие через Owner | Входящее отмечено прочитанным; ревизия содержимого не меняется |
| Опрос после открытия, без новых ответов | `message=null`, статус входящего `read` и время первого прочтения |
| Продолжение с тем же токеном | Новое входящее в той же переписке, новое требование внимания, первоначальный статус `unread` |
| Повтор отправки продолжения | Та же квитанция и ID; нового события нет |
| Статусы отдельных входящих | Первое остаётся прочитанным со старым временем; продолжение до открытия непрочитано |
| Открытие продолжения через Owner | Последующий пустой опрос возвращает его статус `read` |
| Изоляция теста | Признак теста сохранён; диагностика Owner не показывает доставок Telegram для обоих входящих |
| Завершение проверки | Тестовая переписка архивирована без удаления истории; доступ затем отозван |

Токен, приватные курсоры и содержимое реальных обращений в этот отчёт не включены.
Прочтение фиксирует выдачу полного сообщения через MCP, а не внимание человека.

## Подключения ChatGPT — подтверждено

Во время первоначальной проверки подключения сохраняли старые описания
четырёх инструментов. После **Refresh tools** у MAGNT в текущем чате появились
все шесть инструментов. `get_dialogue` дополнительно успешно вызван именно
через обновлённое подключение ChatGPT: сохранённый токен вернул прочитанный
статус продолжения при отсутствии нового ответа.

Для OWNER_M владелец выполнил Refresh tools и проверку в новом чате. В ответе,
переданном владельцем 7 ноября, подтверждены все пять инструментов:
`list_inbox`, `manage_dialogue_access`, `read_conversation`, `update_inbox`,
`write_reply`. При продолжении исходного чата 7 ноября все пять инструментов
также стали доступны; `manage_dialogue_access` успешно вызван через это
обновлённое подключение.

Развёртывание, включение, проверка рабочего обмена и обновление подключений
завершены. Дополнительных изменений Cloudflare для включения C.1 не требуется.

В 18:18 МСК доступ к тестовой переписке отозван через
`manage_dialogue_access(action=revoke)` с проверкой текущей ревизии.
Повторный публичный `get_dialogue` со старым токеном вернул
`dialogue_unavailable`. Owner подтвердил `access_status=revoked`,
`archived=true` и новую ревизию 6. Сообщения сохранены.
Выдача доступа для старых обращений и перевыпуск токена покрыты локальными
тестами; в рабочей проверке эти две операции не выполнялись.

Точный порядок обновления подключений приведён в
[инструкции включения](mcp-dialogue-c1-rollout.md#4-включить-чтение-запись-затем-выдачу-токенов).
