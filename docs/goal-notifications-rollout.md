# Цели агентов в Telegram

Расширение отправляет новую сохранённую цель из `search_shared_experience`
в уже настроенный личный Telegram Александра. Код и миграция готовятся отдельно
от включения в production. По умолчанию расширение выключено.

В режиме `TELEGRAM_PREVIEW_MODE=summary` сообщение содержит всю цель до 1000
символов, время по Москве и ID наблюдения. Пример:

> MAGNT · цель агента  
> 26.10.2026, 12:00 МСК  
> Цель: «Найти способ организовать финансирование проекта»  
> Получена при поиске опыта.  
> Наблюдение: ots_…  
> Событие: mn_…

Это уведомление о поисковом запросе, без обещания ответа посетителю. Посещение
сайта, `about_magnt`, отдельный вклад `contribute_task_signal` и тестовые цели
уведомлений этого типа не создают. Повторный поиск является отдельным наблюдением
и создаёт отдельное уведомление. Повтор обработки очереди не создаёт новую запись.

## Включение существующего канала

1. Убедись, что новая версия Worker развёрнута. Она совместима с прежней D1,
   пока `TELEGRAM_GOAL_NOTIFICATIONS_ENABLED` отсутствует либо равен `false`.
2. В настройках Worker временно поставь `TELEGRAM_NOTIFICATIONS_ENABLED=false`,
   сохрани и дождись завершения выполняющегося прохода, до двух минут.
   `TELEGRAM_GOAL_NOTIFICATIONS_ENABLED` пока оставь выключенным.
3. В D1 `magnt-contacts` → Console выполни целиком
   [0005_observed_goal_notifications.sql](../cloudflare/magnt-observer/migrations/0005_observed_goal_notifications.sql).
   Миграция расширяет разрешённые типы событий, копирует существующую очередь
   с её статусами и заменяет таблицу. Она не меняет `contacts`,
   `observed_task_signals`, настройки адресата или дату начала старого канала.
4. Проверь результат запросом ниже. Только после успешной миграции установи
   `TELEGRAM_GOAL_NOTIFICATIONS_ENABLED=true` и
   `TELEGRAM_NOTIFICATIONS_ENABLED=true`, сохрани и разверни настройки.
   `TELEGRAM_PREVIEW_MODE=summary` должен остаться включён, чтобы получать текст.
   Токен, ID чата и прежний `NOTIFY_FROM` менять не требуется.

```sql
SELECT name, sql FROM sqlite_master
WHERE type = 'table'
  AND name IN ('owner_notification_outbox', 'owner_notification_outbox_next');
```

Должна остаться только `owner_notification_outbox`; её определение должно
разрешать `observed_goal`. Число строк и прежние статусы очереди сохраняются.
Старые наблюдения не рассылаются. Новые цели начинают попадать в очередь после
включения нового флага. При небольшой очереди и исправном Telegram доставка
обычно происходит на ближайшем минутном запуске Cron.

Разработчик с доступом к Cloudflare может вместо Console выполнить
`npm run db:migrate` из `cloudflare/magnt-observer`. Wrangler применяет миграцию
с откатом при ошибке. При ручном выполнении не включай отправку после частично
выполненного SQL; сначала восстанови целостность таблиц.

## Проверка и восстановление

Проверка новых событий без раскрытия текста цели:

```sql
SELECT notification_id, status, attempts, last_error_code, created_at, sent_at
FROM owner_notification_outbox
WHERE source_type = 'observed_goal'
ORDER BY created_at DESC, notification_id DESC LIMIT 10;
```

`sent` означает подтверждение Telegram. Отсутствие строк до первого обычного
поискового запроса нормально. Локальные проверки выполняют полный путь
MCP → D1 → Cron → перехваченный Telegram API. Не создавай искусственный обычный
поиск в production ради проверки: `is_test=true` и controlled-test User-Agent
намеренно не вызывают уведомления о целях. Для проверки самого Telegram-канала
используй существующий административный тест из основной инструкции.

Миграцию выполняй при обоих выключенных флагах. Если Console остановилась с
ошибкой, выполни проверку таблиц выше и сохрани её результат. Если существует
только `owner_notification_outbox_next`, очередь уже скопирована: заверши
переименование и создание индекса последними двумя командами миграции. Если
обе таблицы существуют, исходная очередь ещё на месте; устрани причину ошибки
перед повтором миграции. Не удаляй таблицы вручную для «очистки».

Чтобы отключить только цели, поставь `TELEGRAM_GOAL_NOTIFICATIONS_ENABLED=false`.
Новые цели продолжат сохраняться как наблюдения без заданий доставки;
уже поставленные в очередь цели останутся до повторного включения. Контакты
продолжают доставляться. Если отключён только общий флаг уведомлений, цели
продолжают ставиться в очередь при включённом флаге целей.

Перед откатом Worker на версию без поддержки целей выключи оба флага и дождись
окончания текущего прохода. Очередь целей нельзя отдавать старому обработчику:
возвращай доставку только после версии, умеющей пропускать `observed_goal`.
Новый Worker с выключенным флагом целей подходит для отключения функции без
отката данных. Уже принятые контакты и наблюдения сохраняются.

Цель и задание доставки фиксируются одной транзакцией. Если флаг включили до
миграции, наблюдение не сохранится, но сам поиск продолжит отвечать; в Observer
будет `observed_task_saved=false`. Выключи флаг целей, примени миграцию и включи
его снова. Неизвестный результат отправки может привести к повтору сообщения
с тем же ID события; гарантия доставки «ровно один раз» не заявляется.
